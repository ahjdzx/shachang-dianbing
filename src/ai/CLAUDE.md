# ai/
> L2 | Parent: ../../CLAUDE.md

棋手层。它只依赖 engine。全部是纯逻辑，可以在 Node 里无界面运行。
暗棋的做法：按信念抽样出若干个「兵种全部已知」的世界，每个世界做普通的 alpha-beta，再对走法取平均。所以 search 和 evaluate 不知道暗棋的存在。

## 成员清单

rng.js: 种子随机数。同一个种子产生同一串数；fork 派生互不干扰的子流。
knowledge.js: 暗棋边界。它为一方维护对敌方每个棋子的信念（位掩码），只从公开事实更新：布阵约束、谁动了、是否拐弯、交战结果、对方亮没亮旗。大小关系从 engine 的 battle 反推，不另写一份表。observe 生成一方的视图；sampleWorld 用二分图匹配按信念补全一个不超编制的世界。
formations.js: 阵型库。四套阵型，各带一句给人看的说明。人点兵用 arrange 原样摆出（可镜像）；电脑用 deploy 在上面加随机镜像和军官对调。地雷、炸弹、军旗和大本营里的子不参与对调。
evaluate.js: 一个确定世界的静态估值：兵力、向前压、逼近敌旗、守住己旗。
search.js: 一个确定世界里的 alpha-beta，写成生成器分片推进。根节点每个走法用全窗口拿精确分，因为 brain 要拿它们取平均。静态搜索只多看不亏的交战；军旗被贴身时强制看完所有应法。
brain.js: 决策。第一轮在所有世界里浅搜全部走法，第二轮对前几名按完整深度重算；分数 = 均值 + 胆量 × 波动，再用温度抽选。它还定义四种性格和两种胜率（全知、暗棋视角）。
commentary.js: 解说。同一步棋按观众认不认得交战双方，写出不同的记谱和解说。

## 约定

- brain.think 的入参是 observe() 的视图，不是对局状态。不要把 state 或真实棋盘传进 brain。
- MATE 取 8000，不取天文数字：它要参与多个世界的平均。
- 红黑对称：把局面旋转 180° 并换色，电脑必须走出镜像的一步。所以凡是「按顺序遍历棋盘」又影响结果的地方（走法排序、抽样顺序），都按己方视角排。
- 信念必须始终包含真相。任何改动 learn/settle 的提交都要跑 `npm test` 里的整盘校验。
