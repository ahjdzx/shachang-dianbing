# 沙场点兵 · 桌面军棋

一张低矮漆木桌上的真军棋盘，两支玩具军队在上面自己下完一整盘军棋（陆战棋），带自动导播镜头。默认下的是**暗棋**：两个电脑都看不见对方的兵种，只能靠交战结果推理。随时可以暂停、改设置或接管一方。

在线地址：https://ahjdzx.github.io/shachang-dianbing/ —— 推送到 `main` 后由 GitHub Actions（`.github/workflows/deploy.yml`）先跑测试、再构建并发布到 GitHub Pages。

姊妹项目：[楚河汉界](https://github.com/ahjdzx/chuhe-hanjie)（中国象棋）。两者分层相同。

```sh
npm install
npm run dev        # 开发服务器
npm test           # 规则引擎 + AI 测试（Node，无需浏览器）
npm run bench      # 对局场：批量跑 12 盘，看胜负和比例、步数、耗时
npm run build      # 打包到 dist/（相对路径，放在根路径或子路径都能打开）
npm run preview    # 本地预览打包结果
```

## 分层（严格单向）

```
src/engine/junqi.js   裁判：规则、棋盘拓扑、布阵约束、对局记录。纯逻辑，掌握全部真相
src/ai/               rng 种子随机数 · knowledge 暗棋信念 · formations 阵型库 · evaluate 估值 · search 推演 · brain 决策 · commentary 解说
src/game/match.js     一盘对局：唯一能改变对局状态的入口 commit()，只接受合法走法
src/sim/              show 演出协程 · physics 轻量刚体 · fx 扬尘/爆炸
src/render/           world 桌子棋盘托盘 · figures 十二个兵种的人偶 · director 自动导播
src/main.js           总控：裁判裁决 → 电脑选择 → 演出 → 导播；决定观众是谁
```

演出层只读走法记录，从不写回对局；物理只负责「倒得像」，结果永远由引擎决定。
电脑拿到的只有 `observe()` 给的视图（敌子只剩位置），从结构上就偷看不了；画面上没认出的敌子由总控按 `visible()` 蒙布。

## 规则

- 棋盘 5 列 × 12 行，共 60 个站。两个半场之间是前线：A、C、E 三列有铁路相通，B、D 两列是山界。
- 每方 25 子：司令、军长各 1，师长、旅长、团长、营长各 2，连长、排长、工兵各 3，地雷 3，炸弹 2，军旗 1。
- 布阵：军旗必须在大本营；地雷只能在后两排；炸弹不能在第一排；行营开局空着。
- 走法：公路一次一步。铁路上沿直线走任意远，不能拐弯、不能越子；工兵在铁路上可以拐弯。地雷、军旗不能动；进了大本营的棋子不能再动。
- 行营里的棋子不受攻击；行营有子就进不去。
- 交战：军衔大吃小，同级同归于尽。炸弹与任何棋子同归于尽。只有工兵能排雷，其余棋子踩雷阵亡、地雷留下。任何能动的棋子碰到军旗即夺旗。
- 司令阵亡，本方军旗亮出。
- 胜负：军旗被夺、无棋可走判负。三次重复局面、连续 80 步（半回合）没有交战、500 步上限判和。
- 记谱用坐标：列 A–E（红方左手起），行 1–12（红方底线起）。例如 `师长 A6×A7 胜`、`工兵 E3→A6`。
- 加载时自检：棋盘拓扑的六个定数（10 行营、4 大本营、32 个铁路站、133 条边、35 条铁路边）加固定布阵的开局走法数 34，结果写入控制台，失败时界面左上角显示红色警告。测试还校验 perft：34 / 1159 / 36185。

## 暗棋与电脑

- **信念**：每一方对敌方每个棋子记一组「还可能是什么」。来源只有公开事实：布阵规则、谁动过（动了就不是地雷和军旗）、在铁路上拐弯（只能是工兵）、交战结果（赢了说明更大，输了说明更小或撞了雷，同归于尽说明同级或有炸弹）、对方亮没亮旗（敌子阵亡而旗没亮，它就不是司令）；再数编制收紧（司令只有一个，认出一个，别的就都不是）。
- **推演**：按信念抽样出若干个「兵种全部已知」的世界（深度 2 抽 10 个），每个世界做 alpha-beta 加静态搜索，再对每个走法取平均。军旗被敌子贴身时强制看完所有应法，不会「按兵不动」丢旗。
- **胆量**：分数 = 均值 + 胆量 × 波动。胆大的性格敢拿大子去撞暗子，谨慎的宁可稳一点。
- **性格与阵型**：闪电战、铁壁、诡道、步步为营，各自偏好不同阵型（三角雷、铁路快攻、中路突破、空城计）。布阵在模板上随机镜像、对调军官。
- **温度**：在分数接近的几步里按 softmax 抽选；高于 0.55 时偶尔故意失误。
- **明棋**：规则可切到明棋，双方兵种全部公开。实现上只是「信念一开始就全部确定」，没有第二条代码路径。
- **种子**（6 位）驱动一切随机。每盘棋还记一份「对局脚本」：初始设置、按步记录的设置改动和你亲手下的每一步。「重放」按脚本精确复现原局；重放途中你一改设置或接管，就从那一步起分岔。
- **红黑对称**：把局面旋转 180° 并换色，电脑走出镜像的一步（测试逐步校验）。两边是同一个棋手，差别只在谁先走。
- 实测（`node test/arena.mjs 80 2`：深度 2、温度 0.35、暗棋，80 盘）：红 46 胜、黑 32 胜、和 2；73 盘夺旗、5 盘无棋可走、2 盘判和；平均 102 步、27 次交战；每步平均 34 ms，最慢 487 ms，分片执行，界面不卡。
- 先手对照（同一批种子，红先、黑先各 40 盘）：红先时红 21 : 黑 18，黑先时黑 22 : 红 18。胜率跟着先手走，不跟着颜色走；先手约占五成四，样本不大，只能说优势不明显。

## 观众与迷雾

- **全知观战**（默认）：两边的兵种都看得见。
- **红方 / 黑方视角**：没认出的敌子蒙成一顶军帐，旗上写「？」；棋谱里叫「暗子」，解说附上能推出的范围（例如「对方比团长大，或是地雷」）；胜率条只用这一方看得见的信息估算。
- 蒙着布的棋子外形、待机、步态全都一样，交战时演通用动作：爆炸、踩雷、炸弹的木橇滑行这类特殊演出本身会泄密。对手的性格和阵型显示「对手保密」。阵亡的暗子不揭示。终局后全部亮开。
- 你接管一方时，视角自动切到那一方，镜头切到「入座」（己方身后的固定机位）。

## 演出

- 铁路上滑行，公路上迈步；工兵沿铁路的折线拐弯。经过别的棋子时对方让位，过后弹回。
- 炸弹：火球、黑烟、冲击环，镜头抖动，两个棋子一起炸飞。踩雷：进攻方被炸飞，地雷留在原地。工兵挖雷：铲两下，地雷被掀走。
- 被吃的棋子交给刚体模拟：重力、弹跳、摩擦、翻滚、静止，然后扶正、抬进桌边同色的盒子（红子进红盒，黑子进黑盒）。炸弹在火球里没了影，烟散后也落进己方的盒子。两个盒子里各有几个子，就是双方各丢了几个。
- 静止的人偶会呼吸、轻摇，旗帜随风飘动。风向始终垂直于镜头视线，所以每面旗都正对镜头。

## 入座点兵

打开页面时，两支军队在桌上自己下着。想自己下：

1. 点屏幕下方的「我来下一盘」。演示停下，镜头滑到你这一方身后，桌边出现开局牌。
2. 在牌上选三样：**执子**（执红先行 / 执黑后行）、**阵型**（四套现成阵型，可左右对调）、**对手**（新手 / 熟手 / 高手）。换阵型时，你的 25 个子当场走到新位置。
3. 点「开局」。对手从你坐下那一刻起就蒙着布，它的性格和阵型不公开。

下完后选「再来一盘」或「观战」。中途想走，展开「设置」点「离座」，这盘作废。上次的选择记在本机浏览器里，下次直接沿用。

你点的阵和执子方会记进对局脚本，所以「重放」连你的布阵一起复现。三档对手只是温度和推演深度的预设：新手（温度 0.8、深度 2）、熟手（0.35、2）、高手（0.1、3）。档位之间实测各 40 盘、换边：熟手对新手 26 胜 13 负 1 和，高手对熟手 24 胜 14 负 2 和，高手对新手 29 胜 9 负 2 和——强弱顺序成立，差距是「明显但不悬殊」。

## 操作

- 空格：暂停 / 继续；速度 0.25–3×；推演深度 2/3/4；镜头：自动导播 / 自由视角 / 俯视 / 入座（右键拖动或滚轮会切到自由视角）。
- 红方、黑方可分别切到「我来下」：点己方棋子显示可走点（绿圈是空位，红圈是交战），再点目标点。
- 俯视和竖屏入座时镜头很陡，旗面会后仰并放大成名牌，从上往下也认得出每个子。

## 手机

- 竖屏下设置收成顶部一条：「战况」打开棋谱与兵力表的底部抽屉，「设置」展开全部选项，「暂停」随手可点。
- 视野随屏幕比例自动放宽；俯视的高度按画面算，棋盘正好铺满屏宽；自动导播的待机镜头改为在红方身后左右摆，棋盘的长边顺着屏幕的长边。
- 接管一方后，「入座」在竖屏上是一个铺满屏宽的陡视角，最近一排的列距约 65px、行距约 46px（390px 宽的屏幕上），手指点得准。
- 轻点才算选子和落子；拖动是转镜头，不会误触。双指一碰切到自由视角，之后单指转、双指缩放。
- 触屏设备自动降一档像素比和阴影贴图。以上在桌面浏览器的 390×844 视口里验证过，没有在真机上测过帧率。
